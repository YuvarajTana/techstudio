03 / THE SYSTEM BEHIND THE CANVAS

Your browser authors. Your local services save.

Canvas editing and its frame preparation happen in the browser. Lesson Video uses shared scenes in a local Remotion worker. FastAPI handles accounts, persistence, assets and render jobs. MySQL stores project data; local disk stores media.

Two local video paths

Optional external services

AI chat/artwork, connected stock assets and some fonts require internet. Provider keys stay in the backend environment. Manual diagrams do not need AI generation.

Local does not mean fully offline. Package installation, remote fonts and connected asset libraries can use the network. Prepare and reopen your lesson before teaching without internet.
04 / LOCAL SETUP

A repeatable start
on your Mac.

The included launcher owns a separate MySQL instance. It keeps project data under .local and leaves your system database directory alone.

cd /Users/yuvarajtana/team-projects/canva1-main
./scripts/setup_local.sh
./scripts/start_local.sh

Run setup once. Run start each session. Ctrl+C or ./scripts/stop_local.sh stops the services and preserves data.

Open local product ↗
  1. Check prerequisites

    Node 22.12+ or 24; Python 3.10+ (3.12 tested); MySQL; FFmpeg. This Mac’s default Python 3.9 is too old.

  2. Install and initialize

    Setup creates a virtual environment, installs root workspace dependencies, prepares the render browser and generates private local credentials. Existing environments are preserved.

  3. Start and check readiness

    MySQL 3307 → API 5001 → frontend 5173 → render worker. Worker health is /api/health/lesson-video. API health is /health, and database health is /api/health/database.

  4. Create your local account

    Register on the local login screen. A hosted account will not automatically exist in this database.

  5. Build and back up

    Back up the database, environment and media together. Save final videos outside the temporary render folder.

Already have a MySQL database, or use Windows?

Use the manual instructions in docs/LOCAL_SETUP.md. Configure a dedicated development database/user, set backend/.env and frontend/.env.local, then run Uvicorn on 5001, Vite on 5173 and npm run video:worker in separate terminals. The bundled launcher uses Unix sockets and is intended for macOS/Linux; only macOS was exercised here.

Why might AI generation fail after setup?

Keys are optional and were not supplied or tested. The inherited Gemini 2.0 Flash default was retired June 1, 2026. Select a currently supported model and verify provider compatibility before using AI. Google model lifecycle.

06 / WHAT TO IMPROVE NEXT

Build trust before adding breadth.

The next product step is a reliable path from teacher authoring to student consumption. These are recommendations; the learner features below have not been implemented.

Proposed roadmap
  1. P0Reliable saves and recovery

    Serialize writes, surface failures and persist undo/redo. Test delayed saves and reloads so teachers can trust their work.

  2. P0A safe read-only learner view

    Render shared pages without editor access. Enforce visibility and asset permissions; support revocation.

  3. P1Structured lessons and reusable packs

    Lesson Video now stores outcomes, prerequisites, sources and scenes. Extend this with reusable domain packs and reviewed practice material.

  4. P1Complete classroom output

    Lesson Video now exports landscape MP4. Add multi-page PDF, transcripts, captions and accessible text alternatives.

  5. P2Practice, progress and scalable operations

    Lesson Video jobs now recover after interruption. Add learner responses and feedback, split large editor modules and improve media portability.

Proposed content model

Course → Lesson → Scene

Lesson = audience + objectives + prerequisites + sources.
Scene = explanation + visual + narration + practice.
Domain pack = reusable vocabulary, templates and examples.

Use now

Visual authoring + your existing LMS

Keep curriculum notes and answer keys externally. Create and export content here. Use your classroom or LMS for assignments, feedback and learner progress.

Teacher workflow

Draft → Preview → Render

Open Quick Create → Create Lesson Video. Set the audience and outcome, edit scenes, scrub the preview and render a saved revision. Follow progress and download the video. The local worker keeps rendering after the editor tab closes, while local services stay running.

Programmatic workflow

JSON → Validate → Generate

A CLI or authenticated API accepts the same lesson format. Create explicit audience variants, then track each render. The current template supports English text. AI can draft the content later; the renderer uses supported scene types.

# From the project root, after setup
npm run video:render -- --spec docs/examples/lesson-video-api-request.json --out .local/exports/api-request.mp4

Or open the product, log in and select Quick Create → Create Lesson Video. Import JSON, edit, preview and render. Completed jobs offer MP4, poster and manifest downloads.

Does the Audit score certify educational quality or accessibility?

No. It checks visual heuristics such as contrast, typography and alignment. Review factual correctness, reading order, motion, captions and learner understanding separately.
